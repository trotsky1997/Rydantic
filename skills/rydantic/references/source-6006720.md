## Per-call Model policy contract

Use `#[model(validate_with_context = allowed)]` on a field. The callback has
signature `fn(&T, &Context) -> Result<(), ValidationError>` and obtains exact-type
application data using `ctx.require_data::<Policy>()?`. Supply owned, static,
`Send + Sync` data as `Arc<Policy>` to `Model::parse_json_with_context`.
A required but absent payload yields `context_missing`; another payload type
returns `context_type_mismatch`. Both are structured validation errors at the
field location, not panic recovery or implicit defaults.

The model does not retain context. Resupply it to `validate_with_context` and
`dump_json_with_context`; ordinary validation is context-free and must not skip
the required policy. Changing the supplied policy can reject a previously parsed
model. The [consumer](../assets/source-6006720/tests/contracts.rs) checks the inclusive
policy boundary, rejected neighbor, missing/wrong payload, revalidation and
released ownership. It is an API regression fixture, not external adoption or
an Agent performance trial.

Context is not `UnwindSafe`/`RefUnwindSafe`; do not add blanket `AssertUnwindSafe`
wrappers. Failed untagged alternatives share payload effects without rollback.
High-level Serde, Axum and SQL entry points do not automatically forward this
business context. These boundaries are documented in the [pinned context guide](https://github.com/trotsky1997/Rydantic/blob/60067205276e314653f46a75c213ec1756c7ad7c/docs/models/validation-context.mdx).
