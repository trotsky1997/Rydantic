## 0.7.0 · Stable

Published on 2026-10-21 as stable: [runtime](https://crates.io/crates/rydantic/0.7.0) and [derive](https://crates.io/crates/rydantic-derive/0.7.0). Install with `rydantic = "=0.7.0"`; the runtime pins derive to the same exact version. The [guarded publication workflow](https://github.com/trotsky1997/Rydantic/actions/runs/39545120139) succeeded for source commit [09ad96d](https://github.com/trotsky1997/Rydantic/commit/09ad96d4852ae187d5ddeac096c690eef723a127). Both downloaded registry archives matched their API and sparse-index checksums and the final local packages.

A fresh registry-only consumer passed 48 tests plus 3 isolated settings cases, 2 alternate-configuration tests, and 2 direct-macro tests in each configuration mode. Both packages resolved from crates.io without path patches. See the [release record](https://github.com/trotsky1997/Rydantic/releases/tag/v0.7.0) for detailed verification results.

- Promote settings, partial JSON and domain types from the verified betas, with their documented limits. Fix callback-path hygiene and evaluate consumer cfg/cfg_attr before automatic Cap’n Proto schema generation.
- **Breaking from 0.6.0:** explicitly derive Model on every capnp_models struct/enum. Conditional definitions create configuration-specific wire schemas; different feature/target sets are not automatically compatible. Preserve explicit ordinal checks; use fixed/schema-first protocols for shared wire formats.
- SQLite migration guards reject unsupported index layouts rather than losing constraints. Back up data and review migrations; users remain responsible for existing deployments. No automatic production-data migration is performed.
- Core archives contain only runtime and derive. AI is independently released; CLI/codegen remain unpublished source tools. Exact-version Skill/evaluation fixtures remain pinned to their original contracts.

See the [complete changelog](https://github.com/trotsky1997/Rydantic/blob/main/CHANGELOG.md), [Cap’n Proto migration guidance](/integrations/capnp), [migration limits](/integrations/migrations), [settings](/models/settings), [partial JSON](/models/partial-json) and [domain provenance](/domain-types).

## RydanticAI 0.6.0

All three providers and gateway frontends support ordered user image inputs across the nine protocol combinations, including URL references and Base64 images. Typed `Prompt` / `Image` builders work with Agents, Partial and Iterable output. Requests are bounded to 16 MiB with image-specific validation, and replay identity includes compact image digests. The release also carries the multi-turn replay fixes from main. See [image inputs](/integrations/images).

## RydanticAI 0.5.0

The independently versioned [rydantic-ai crate](https://crates.io/crates/rydantic-ai/0.5.0) adds native gateway frontends for `/v1/chat/completions` and `/v1/messages`. [Gateway protocols](/integrations/gateway-protocols) covers all nine frontend/upstream combinations, JSON and SSE, tools, structured output mappings, usage, authentication and bounded native history replay.

Successful stream terminals follow budget settlement. Shared tool-choice and sampling controls map to each upstream protocol. CI includes strict official Python SDK checks for all three frontends.

## RydanticAI 0.4.0

The independently versioned [rydantic-ai crate](https://crates.io/crates/rydantic-ai/0.4.0) supports Responses, Chat Completions and Anthropic Messages upstreams through BASEURL and APIKEY. [API providers](/integrations/api-providers) share typed tools, validation correction, Partial and Iterable streams, usage accounting and gateway routing. Native message history survives same-protocol tool continuations, including through the gateway HTTP interface.

Provider setup uses standard protocol constructors and explicit capabilities. The published crate contains the Rust SDK, gateway and generic examples. Core release versions remain independent.

## RydanticAI 0.3.0

The independently versioned [rydantic-ai crate](https://crates.io/crates/rydantic-ai/0.3.0) adds [structured output streaming](/integrations/structured-output). Core release versions remain independent.

- `Partial<T>` emits provisional JSON snapshots and completes with a fully validated Rust model.
- `Iterable<T>` emits validated elements from an `items` envelope and collects the accepted attempt into `Vec<T>` without a `Clone` bound. Async item validators run once per element per attempt.
- Explicit model-call numbers and reset reasons cover validation correction and tool continuations. Completion retains usage and history. Cancellation, deadlines, bounded queues and byte/depth/item limits cover stream processing.
- Preserve native Responses events and support custom providers without HTTP features. Non-streaming providers fall back to processing their completed response.

## 0.7.0-beta.4 · Published prerelease

Published on 2026-10-20: [release and verification](https://github.com/trotsky1997/Rydantic/releases/tag/v0.7.0-beta.4). The published release record reports verified archives and a fresh registry-only consumer (46 tests plus 3 isolated environment cases). Opt in with `rydantic = "=0.7.0-beta.4"`.

- Add individually optional [phone, country and currency types](/domain-types), with pinned offline catalogs and explicit local validation rules. Phones are not proof of reachability/ownership; currencies include legacy, fund and special entries, not a current-tender guarantee. Preserve upstream/data-source attribution.
- The source-only JSON Schema-to-Rust developer tool remains unpublished (`publish = false`), outside the two core package archives. The source workspace also contains independent AI/Jev work; neither is part of the core archives or uploaded by this release.
- No new breaking API change from beta.3. Preserve the explicit Model derive upgrade, backup/manual migration responsibilities and partial JSON safety limits below.

## 0.7.0-beta.3 · Published prerelease

Published on 2026-10-20: [release and verification](https://github.com/trotsky1997/Rydantic/releases/tag/v0.7.0-beta.3). Opt in with `rydantic = { version = "=0.7.0-beta.3", features = ["partial-json"] }`. Stable remains 0.6.0.

- Add bounded [partial JSON snapshots](/models/partial-json), separate from strict streaming and Model validation. Incomplete containers, numbers and literals may be recovered; all incomplete strings/keys are rejected.
- Hard limits: 1 MiB input and 64 nested containers. The pinned parser's 4300-digit integer-part ceiling is reported as unsupported, never rounded; no equivalent fractional/exponent limit is claimed.
- Preview values are not validated business data. Require the producer's final document, `Complete` and ordinary Model validation before consequential actions. Successful values can contain secrets; repeated prefix reparsing can be quadratic.
- Preserve beta.1 breaking derives, migration guards and backup responsibilities below. No new breaking API change from beta.2. New JSON Schema-to-Rust code generation and phone/country/currency domain types are excluded.

## 0.7.0-beta.2 · Published prerelease

Published on 2026-10-20: [release and verification](https://github.com/trotsky1997/Rydantic/releases/tag/v0.7.0-beta.2). Opt in with `rydantic = "=0.7.0-beta.2"`. Stable remains 0.6.0.

- Add opt-in [settings](/models/settings): explicit ordered JSON, environment, strict dotenv-subset and flat secrets-directory sources, existing Model validation, and redacted source errors. This is not full pydantic-settings compatibility.
- Accept exact zero with arbitrarily large positive or negative JSON exponents during integer normalization. Nonzero overflow, fractions, malformed JSON and numeric strings remain invalid.
- Preserve the beta.1 explicit-derive contract and SQLite migration guards. No new breaking API change from beta.1; follow the upgrade and backup guidance below when coming from 0.6.0.

Partial JSON, the new JSON Schema-to-Rust code generator, and phone/country/currency domain types are not included in this release.

## 0.7.0-beta.1 · Published prerelease

Published on 2026-10-20: [release and verification](https://github.com/trotsky1997/Rydantic/releases/tag/v0.7.0-beta.1). Both packages are available with explicit opt-in `rydantic = "=0.7.0-beta.1"`. This version does not contain settings. Stable remains 0.6.0.

- Breaking: every struct and enum inside `capnp_models`, including nested models, must explicitly derive `Model`. No automatic derive insertion or compatibility layer remains.
- Fix relative Cap'n Proto compiler paths, including Windows drive-relative and root-relative paths; imported aliases for `Model` are resolved by Rust.
- Reject SQLite rebuilds with non-BINARY collation or descending index order, including primary-key indexes, instead of silently losing semantics. Ordinary BINARY ascending indexes, no-op migrations and native rename-only changes remain supported.

Review the [Cap'n Proto migration guidance](/integrations/capnp) and [database migration limits](/integrations/migrations). Back up databases and test migration plans before upgrades. Users are responsible for existing deployments and data; unsupported custom SQLite schemas need a reviewed manual migration, not removal of constraints to bypass the guard.

### Main and beta rhythm

Main stays releasable. Breaking or substantial changes first receive numbered beta packages and GitHub prereleases; no permanent beta branch is maintained. Stable promotion is not time-based: require exact-commit integrated CI, package verification, a fresh registry-only consumer, and no release-blocking issues. Stable 0.7.0 is a new immutable version with fresh validation, not a renamed beta.

## 0.6.0 · Model-driven database migrations

- Automatic migration plans for SQLite, PostgreSQL and MySQL.
- Column renames, SQL defaults, indexes, foreign keys and explicit destructive changes.
- Migration history, stale-plan checks and database-specific concurrency locks.
- Unified SQL API with independent database drivers.

The old SQLite-specific codec hooks and duplicate DDL entry points were removed. Enable the driver you use, derive `Model` and `SqlModel`, and call `YourModel::migrate(&pool).await?` to create or upgrade a table.

See the [0.6.0 release](https://github.com/trotsky1997/Rydantic/releases/tag/v0.6.0) and the [automatic migration guide](/integrations/migrations).
